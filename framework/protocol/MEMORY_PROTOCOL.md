# MEMORY_PROTOCOL.md — 记忆协议

> **版本**：`1.1` ｜ 轮次 `r03` ｜ 更新 2026-10-11 ｜ 权威源 `VERSION_INDEX.md`
> 版本规则见 `docs/VERSIONING_DOCS.md`

> **本文件定义记忆层的读写规则。**
> 它是本仓库与"一份数据分析包"的**唯一实质区别所在**。
>
> 一份分析包产出结论。本仓库**记住结论、记住怎么错的、记住还没做什么**。
> 本协议就是这套记忆的存取规范。

---

## 0. 四类记忆与它们的半衰期

| 记忆 | 位置 | 记什么 | 半衰期 | 写策略 |
|---|---|---|---|---|
| **结论** | `memory/facts/FACTS.jsonl` | 世界是什么样的 | 长（除非被推翻） | **追加**，带取代链 |
| **日志** | `memory/journal/roundNN.md` | 每轮做了什么、为什么 | 永久留档，不重读 | 每轮一文件，只增 |
| **教训** | `memory/lessons/LESSONS.md` | 我们怎么把自己搞错的 | **永久有效** | **只增不删** |
| **工作记忆** | `memory/workbench/*` | 还没做完的 | **极短** | 高频更新，可删 |

**为什么要分四类**：因为它们若混在一起，短命的东西会淹没长寿的东西。
尤其**教训必须独立**——它是唯一"读一次省几小时"的记忆类型，
混在错误清单里就没人单独读它，于是重犯。

## 1. 结论台账 `FACTS.jsonl`

### 1.1 格式

**JSONL**（每行一个 JSON 对象），受 `spec/fact.schema.json` 约束。
选 JSONL 而非 JSON 数组/数据库的理由：**追加式写入不产生 diff 噪声**，
git 里每新增一条只多一行；也便于 `grep` 与流式处理。

### 1.2 状态机

```
                    ┌──────────────┐
    新结论 ────────→│ established  │ （证据充分，可被引用）
                    └──────┬───────┘
                           │ 发现证据不足
                           ↓
                    ┌──────────────┐
                    │  tentative   │ （可用作方向判断，禁当真值）
                    └──────┬───────┘
                           │ 被新证据推翻          被新结论取代
              ┌────────────┴────────────┐
              ↓                         ↓
      ┌──────────────┐          ┌──────────────┐
      │   refuted    │          │  superseded  │
      └──────────────┘          └──────────────┘
        （禁止引用，留档）      （禁止引用，须填 superseded_by）
```

**注意**：`tentative` **不必然**走向 `refuted`。
`F-0004` 是 `established` 但置信度仅 ★★★☆☆ —— 它是**受模型约束的估计**，
不是"暂时不确定"。**状态与置信度是两个独立的维度**：

- `status` 回答"证据是否成立"
- `confidence` 回答"证据有多强"

一条 `established` + ★★★☆☆ 的结论（如 F-0004）是合法的：
它的估计过程没错，但结论的精度受模型假设限制。

### 1.3 演化链（本仓库记忆的核心）

```jsonc
// 旧条
{"id":"F-0007","status":"superseded","superseded_by":"F-0006", ...}
// 新条
{"id":"F-0006","supersedes":"F-0007", ...}
```

规则：

1. **双向必须一致**，`validate` 会检查
2. **id 永不复用**。推翻一条结论，就新增一条，不回收编号
3. **被推翻的结论保留**，标 `refuted` / `superseded`，**不删除**

### 1.4 为什么被推翻的结论必须保留

> 删除会让下一轮**重走同一条弯路**。

`F-0007`（"2015 年断点"）已被 `F-0006`（"2013-08"）取代。
它现在没有任何引用价值 —— 但它是**"自然年硬切不可用"这条教训的原始证据**（L3）。
如果删掉 `F-0007`，后来的 AI 可能重新按年切一次，
得到同样的错误结论，再花一轮才发现。

**保留错误结论 = 保留"这条路走过"的信息。**

### 1.5 `caveats` 的强制约定

`spec/fact.schema.json` 未把 `caveats` 列入 `required`（为了兼容性），
但**本仓库约定它必须非空**。

**每条 caveat 都必须能转化为一个开放问题。** 这是自我迭代的动力源：

```
F-0004 的 caveat: "封顶稀释：1 亿封顶触发后收益 < 121%"
        ↓
Q-004: 把封顶加进条件模拟后，净值是多少？
        ↓
T-003（P0 待办，带脚本路径与验收判据）
        ↓
round03 的 TASK_BRIEF 选题
```

**若一条 caveat 无法转成问题**，它大概率是空话（如"需谨慎"），应删掉或重写。

### 1.6 置信度 1–5 的标准

| 值 | 含义 | 典型证据 | 可否作为不变量 |
|---|---|---|---|
| 5 | **解析可证 / 精确枚举真值** | 数学推导、全组合枚举 | ✅ 可直接依赖 |
| 4 | **强观测 + 多源交叉确认** | 观测 + CI + 分期稳健 + 多奖级 | ✅ 需声明适用条件 |
| 3 | **依赖模型的估计** | 条件模拟（有自由参数校准） | ⚠️ 仅作方向判断 |
| 2 | 弱迹象 | 单一观测，无 CI | ❌ 不可引用 |
| 1 | 猜测 / 已推翻 | — | ❌ 禁止引用 |

**必须写 `confidence_basis`**，且建议明确写出属于「解析可证」「观测+CI」还是「模型估计」
—— 这三者的强度差异是本仓库最看重的区分（见 `LESSONS.md` L8）。

### 1.7 ★ `claim_type` —— 证据类型（必填，5 选 1）

置信度回答「**有多可信**」，`claim_type` 回答「**靠什么立住**」。
前者是程度，后者是**失效方式** —— 两者正交，缺一个就无法判断能不能引用。

**判据不是「用了什么方法」，而是「它会在什么情况下变错」**：

| `claim_type` | 失效方式 | 因此强制 | 例 |
|---|---|---|---|
| `analytic` | 只有**模型定义**错了才会错 | 不得带 `p_value` / `ci95`（解析量没有抽样误差） | F-0001（组合数恒等式） |
| `empirical` | **数据换了 / 时段移位**就会错 | 必须声明 `data_version` + `n_observations` | F-0003（效应已从 2.11 衰减到 1.25） |
| `simulation` | **模型假设**变了就会错 | `effect` 须含 `n_sim` 或 `rng_seed`；`caveats` ≥ 2 条 | F-0004 / F-0017（121% vs 41.4%） |
| `documentary` | **官方规则文本**变了就会错 | 必须声明 `rules_epoch` | F-0002 / F-0014 |
| `methodological` | 关于**方法本身**的判断 | `caveats` 非空（价值全在失效边界） | F-0007 / F-0018 |

**为什么值得单列一个必填字段**（而不是继续只在 `confidence_basis` 里"建议写明"）：
「建议写明」是**文档层**的约束，写不写全凭自觉；`claim_type` 是**结构层**的约束，
填错会被 `validate --facts` 按类型拒收。F-0004 的 121% 与 F-0017 的 41.4%
是同一个模型的两个口径 —— 差距来自假设而非数据，若标成 `empirical`
就会误导消费者以为"换个数据集就能解决"。

> **同案同判**：取代链上的两条结论（F-0015 → F-0016）性质相同，
> 分类必须一致，否则演化链会出现"同一个判断换了标签"。

## 2. 教训库 `LESSONS.md`

### 2.1 准入标准

> **一条教训的合格标准：它能阻止下一轮犯同样的错。**

| 不合格 | 合格 |
|---|---|
| "分析要谨慎" | "对重尾变量禁止比较均值，改用中位数或 GLM" |
| "注意方法选择" | "小期望频数格禁用渐近卡方，改蒙特卡洛精确检验（B≥10000）" |

### 2.2 必含四段

| 段 | 内容 | 为什么必须有 |
|---|---|---|
| **症状** | 什么情况下会发生 | 让执行者能**自检** |
| **后果** | 会导致什么错误结论 | 说明为什么值得记 |
| **正确做法** | 具体的方法 | 给出**可执行**的替代 |
| **检测方法** | 怎么早发现 | ★ **从"记录错误"升级为"防止错误"** |

第 4 段是 v4 的 `05_known_errors.md` **没有**的。
补上它，教训从"事后复盘"变成"事前检查清单"。

### 2.3 只增不删

即使某条教训后来被证明不适用，也应**新增**一条说明，而非删掉原来的。
"我们曾经这么想"本身是需要保留的信息。

### 2.4 关联要求

每条教训**必须关联**：

- 至少一个具体的 `F-xxxx`（触发它的结论）
- 复现脚本路径

**孤立的教训 = 感慨**，不是记忆。

## 3. 工作记忆 `workbench/`

### 3.1 三文件分工

| 文件 | 内容形态 | 例 |
|---|---|---|
| `OPEN_QUESTIONS.md` | "某个量是多少"（**无方向**） | 后区撞号系数是多大？ |
| `HYPOTHESES.md` | "我认为 X 是 Y 的原因"（**有方向**） | 连号偏好源于随机性错觉 |
| `TODO.md` | "具体动手做什么"（**可执行**） | 用 NegBin 复算 IRR |

### 3.2 生命周期

```
OPEN_QUESTIONS 的问题（无方向）
    ↓ 形成方向性猜测
HYPOTHESES 的假设（有方向，未验证）
    ↓ 通过检验
FACTS 的结论（已验证）
    ↓ 若被推翻
status=refuted / superseded（保留在台账）

TODO 的待办（可执行）
    ↓ 完成
删除 + HANDOFF 记录
```

**方向性**：假设可升级为结论，但结论**不会**退回假设。
结论被推翻后保留在台账标 `refuted`。

**待办可删**（与结论/教训不同）—— 它的价值已在结论里兑现。
但删要经 `HANDOFF.md` 记录。

### 3.3 状态标记

| 状态 | 用于 | 含义 |
|---|---|---|
| `open` | 问题 | 待解 |
| `answered (→ F-xxxx)` | 问题 | 已解，附结论 id |
| `blocked` | 问题 | 当前数据无法回答，**须写明缺什么数据** |
| `unverified` | 假设 | 待检验 |
| `verified (→ F-xxxx)` | 假设 | 已证实 |
| `refuted (理由)` | 假设 | 已推翻 |
| `unverifiable_with_current_data` | 假设 | 不是被推翻，是**数据答不了** |

> `unverifiable_with_current_data` 与 `refuted` 的区别很重要。
> `H-003`（摇奖设备假设）是前者 —— 它是**唯一能推翻 F-0001 的路径**，
> 标为"数据答不了"而非"已推翻"，是为了保留这个可能性，
> 同时不让它污染当前分析。

## 4. AI 读写路径（标准操作）

### 4.1 读（开始一轮）

```
1. AI_CONTEXT.md                          ← 单一入口
2. memory/lessons/LESSONS.md              ← ★ 先读这个
3. games/<g>/iterations/roundNN/TASK_BRIEF.md
4. memory/facts/INDEX.md                  ← 速览
5. memory/workbench/{OPEN_QUESTIONS,HYPOTHESES,TODO}.md
6. memory/facts/FACTS.jsonl               ← 仅在需要精确数字/caveats 时
7. memory/journal/roundNN-1.md            ← 仅在需要过程背景时
```

**为什么 `LESSONS.md` 排第二**：它最省时间。读懂 9 条禁令，
避免的是历史上已经付过学费的错误。

**为什么 `FACTS.jsonl` 排在 `INDEX.md` 之后**：`INDEX.md` 是速览，
先定位再读 JSONL 的精确行，比通读 15 行长 JSON 高效。
**但引用任何数字前必须回到 JSONL 读原条**（含 `caveats`）。

### 4.2 写（收一轮）

**必须全部完成，缺一不可：**

| # | 动作 | 目标文件 |
|---|---|---|
| 1 | 追加新结论 | `memory/facts/FACTS.jsonl` |
| 2 | 更新被取代的结论（双向） | 同上 |
| 3 | 追加新教训（含检测方法） | `memory/lessons/LESSONS.md` |
| 4 | 更新问题池 | `memory/workbench/OPEN_QUESTIONS.md` |
| 5 | 更新假设池 | `memory/workbench/HYPOTHESES.md` |
| 6 | 清算待办 | `memory/workbench/TODO.md` |
| 7 | 写轮次日志 | `memory/journal/roundNN.md` |
| 8 | 重生成索引 | `memory/facts/INDEX.md`（`cli/main.py index`） |
| 9 | 校验 | `python cli/main.py validate --all` |

**第 4 步的传导最关键**：新结论的每条 `caveat` → 逐条转为 `OPEN_QUESTIONS`。
省掉它，`caveats` 就是装饰；留下它，系统有自我驱动的下一轮任务。

## 5. 禁止事项

| 禁止 | 后果 | 正确做法 |
|---|---|---|
| 修改已发布结论的 `id` | 破坏所有引用锚点 | id 永久 |
| 删除被推翻的结论 | 下轮重走弯路 | 标 `refuted`/`superseded` 保留 |
| `supersedes` 单向填写 | 演化链断裂 | **双向**填，`validate` 会查 |
| 结论不写 `caveats` | 下游无法判断失效边界 | 必填 |
| 假设写进 `FACTS.jsonl` | 台账污染，下游引用未验证项 | 假设先放 `HYPOTHESES.md` |
| 待办写进 `FACTS.jsonl` | 同上 | 待办进 `TODO.md` |
| 教训写成泛泛的"要谨慎" | 无人受益 | 必须具体到方法 |
| 教训不关联结论与脚本 | 变成孤立的感慨 | 必须关联 `F-xxxx` + 脚本 |
| 只写日志不更新工作记忆 | 下轮不知从哪继续 | 每轮清算 workbench |
| 把 `source` 写成不存在的路径 | 不可追溯 | `validate` 会检查文件存在性 |

## 6. 与外部世界的边界

记忆层是**内部**的。外部消费者**不应**读取 `memory/`。

| 层 | 消费者 | 稳定性 |
|---|---|---|
| `memory/` | 本仓库的 AI/人 | 内部演进，随轮次变化 |
| `games/<id>/strategy/strategy.json` | **外部工具** | 受 `spec/strategy.schema.json` 约束，稳定 |
| `spec/*.schema.json` | 所有人 | 稳定契约，破坏性变更须提升主版本 |

`strategy.json` 里的 `evidence_refs` 与 `evidence_index` 是**外键 + 摘要**：
外部工具要校验策略时，只需读 `evidence_index`（含 id / claim / status / confidence），
**不必读整个 `FACTS.jsonl`**。这保证了内部记忆可以自由演进，
而对外契约保持稳定。

## 7. 记忆的自我修复

### 7.1 检测漂移

`INDEX.md` 应由 `FACTS.jsonl` 自动生成（`cli/main.py index`）。
手写会漂移 —— 这是已知问题，见 `TODO.md` 的 `T-041`。

### 7.2 检测失效

若 `source` 指向的文件被修改，结论可能已失效。
当前**无自动检测**，见 `TODO.md` 的 `T-042`（证据哈希）。

### 7.3 检测孤儿

一条结论若既无 `source` 存在、又无脚本可复现 —— 它应降级为 `tentative`。
`validate` 会检查 `source` 与 `evidence.script` 的文件存在性。

## 8. 最后一条

> **本协议的一切设计都服务于一个目标：让下一轮比这一轮起点更高。**
>
> - `caveats` 强制非空 → 缺陷被显式记录而非隐藏
> - 被推翻的结论保留 → 弯路不被重走
> - 教训独立成库 → 单一经验被复用
> - 工作记忆可删 → 不积累沼泽
>
> 如果某个做法让"下一轮更容易接续"，它就是对的。
> 如果某个做法只是让"本轮报告更好看"，它就值得怀疑。
