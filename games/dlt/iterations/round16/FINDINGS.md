## 3. 新结论 F-0048：H-002 的三段单调预测 —— 部分支持

F-0038 已估出 35 个号的相对撞号强度 S_j，但当时只做了**两段**比较
（1-31 vs 32-35，差 0.047，CI 含 0）。H-002 预言的是**三段**单调：
月段 1-12 > 日段 13-31 > 高段 32-35。数据侧零成本，只差一次按假设口径的复算。

| 段 | n | 均值 | sd |
|---|---|---|---|
| 1-12（月） | 12 | **1.0213** | 0.0526 |
| 13-31（日） | 19 | **0.9947** | 0.0392 |
| 32-35（高） | 4 | **0.9580** | 0.0613 |

- 点估计**全序单调成立**
- 1-12 − 32-35 = **+0.0633**，bootstrap CI **[+0.0045, +0.1211]** → 显著（勉强）
- 1-12 − 13-31 = +0.0266，CI [-0.0066, +0.0596] → 含 0
- 13-31 − 32-35 = +0.0367，CI [-0.0200, +0.0872] → 含 0
- **序型置换检验 p = 0.2103** → 三段全序本身未达显著

**结论**：支持「小号段比高号段更容易撞车」，**不支持**「严格按 月>日>高 三段递减」。
H-002 → `partial`。置信度只给 3★（端点 CI 下界仅 +0.0045；32-35 段只有 4 个号）。

> 这里刻意**不**写成「H-002 成立」。点估计单调很容易被当成结论，
> 但 p=0.21 意味着这样的三段全序在随机分配下也有约 21% 概率出现。

与 F-0038 的口径差异已在 F-0048 的 caveats 中写明：F-0038 比 1-31 整段 vs 32-35，
本条比 1-12 月段 vs 32-35；1-12 是 1-31 中信号最强的子集，合并会稀释效应 ——
**整段不显著、月段勉强显著，二者可并存**，不是矛盾。

## 4. 机制建设：任务源派生（★源自救）

r15 待办池可执行候选归零，根因不是「事情做完了」，而是**没有补给通道**。
新增 `tools/derive_tasks.py`，从三处**已在仓库里但没进待办池**的存量派生任务：

| 源 | 取什么 | 本轮产出 |
|---|---|---|
| `OPEN_QUESTIONS.md` | 状态 = `open` 的 Q-nnn | T-062（Q-016，`external-data`） |
| `HYPOTHESES.md` | `unverified` / `partial` 的 H-nnn | T-063（H-001）、T-064（H-002）、T-065（H-003，`unverifiable`） |
| `validate --all` 告警 | 按类别归并 | 本轮 0 条（已还清） |

设计取舍：**只标来源不臆造内容**（方法/判据指向原条目，不二次抄写以免分叉）、
**幂等**（`[derive:…]` 标记，可反复跑）、**资源缺口如实标记**（按 Z 协议不占轮次预算）。

效果：r16 任务书从 r15 的「必做 0 个」恢复为有可执行项。

## 5. 顺带暴露的「写死计数」病（与 L15 同源）

F-0048 入库后 `len(FACTS)` 47 → 48，三处写死的 `== 47` 立刻红 4 项：
`test_claim_type`（1）、`test_evidence_anchor`（1）、`test_flywheel`（2）。

这与 LESSONS 的 L15「校验器禁手写白名单」是同一类病灶：**把会增长的真值写死在断言里**。
后果不是「抓到了变更」，而是「每次增长都要人去改测试」——护栏从自动变成人工。

改法：台账只增不删（superseded 也留在文件里），所以用**下界** `>= 47`；
`test_flywheel` 的总数改由 `FACTS.jsonl` 实读推导，只保留「被推翻 3 条」这个
不随新增变化的判据。
