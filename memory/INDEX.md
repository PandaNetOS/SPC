# memory/ — 记忆层

> **版本**：`1.0` ｜ 轮次 `r02` ｜ 更新 2026-10-11 ｜ 权威源 `VERSION_INDEX.md`
> 版本规则见 `docs/VERSIONING_DOCS.md`

> 这是本仓库与"一份数据分析包"的**唯一实质区别**。
>
> 分析包产出结论；本仓库**记住结论、记住怎么错的、记住还没做什么**，
> 并让下一轮 AI 能在此基础上往前推进而不是重来。

---

## 四类记忆，四种用途

| 目录 | 记什么 | 读者 | 更新方式 |
|---|---|---|---|
| **`facts/`** | **已验证的结论**（世界是什么样的） | 策略生成器、外部工具、（AI 选择性读） | 追加式，带取代链 |
| **`journal/`** | **每轮做了什么、为什么**（过程） | 人类评审、下一轮执行者 | 每轮一个文件，只增不改/不改 |
| **`lessons/`** | **方法论错误**（我们怎么把自己搞错的） | **每一个 AI 执行者，动手前必读** | 只增不删 |
| **`workbench/`** | **还没做完的**（问题 / 假设 / 待办） | 下一轮执行者的任务来源 | 高频更新，易耗 |

---

## 为什么分四类（而不是一个大文件）

因为它们的**生命周期完全不同**：

| 记忆类型 | 半衰期 | 若混在一起会怎样 |
|---|---|---|
| 结论 | 长（除非被推翻） | 被临时待办淹没 |
| 日志 | 永久留档但不重读 | 占据了短记忆的空间 |
| 教训 | **永久有效** | 混在错误清单里，没人单独读它 —— 于是重犯 |
| 待办 | **极短** | 变成永不清理的沼泽 |

> 特别是**教训必须独立**：它是唯一"读一次省几小时"的记忆类型。
> 本仓库把它从 v4 的 `05_known_errors.md`（与错误结论混在一起）里拆出来，
> 并给每条补了「**检测方法**」—— 从"记录错误"升级为"防止错误"。

## 记忆的读写路径（AI 应按此顺序）

```
【开始一轮】读 AI_CONTEXT.md（单一入口）
    ↓
读 games/<id>/iterations/roundNN/TASK_BRIEF.md   ← 这轮要做什么
    ↓
读 memory/lessons/LESSONS.md                      ← ★ 先读这个，避免重犯
    ↓
读 memory/facts/INDEX.md                          ← 速览已有结论
    ↓（需要精确数字时）
读 memory/facts/FACTS.jsonl                       ← 权威源，注意 caveats
    ↓
读 memory/workbench/{OPEN_QUESTIONS,HYPOTHESES}.md ← 从哪继续

【做完一轮】写 HANDOFF.md → 生成下轮 TASK_BRIEF.md
    ↓
新结论 → 追加 FACTS.jsonl（含 caveats 与 source）
新教训 → 追加 LESSONS.md（含检测方法）
新问题 → 更新 workbench/（**caveats 条条变问题**）
本轮过程 → 写 journal/roundNN.md
```

## 三条硬规则

### 1. caveats 不为空

`spec/fact.schema.json` 没有强制 `caveats` 必填，但**本仓库约定它必须非空**。
理由：一条没有减损项的结论，要么是数学定理（这种情况应写明"无减损，解析可证"），
要么是作者没想清楚边界。

**每条 caveat 都会自动变成一个开放问题。** 这是自我迭代的动力机制。

### 2. 被推翻的结论不删除

改 `status` 为 `refuted` / `superseded`，保留在台账里，填好双向的 `supersedes` /
`superseded_by`。删除会导致下一轮重走同一条弯路 —— 而这正是本仓库要消灭的事。

### 3. 教训只增不删

即使某条教训后来被证明不适用，也应**新增**一条说明，而非删掉原来的。
"我们曾经这么想"本身是需要保留的信息。

## 与 `games/` 的边界

| | `memory/` | `games/<id>/` |
|---|---|---|
| 范围 | 跨彩种 | 单一彩种 |
| 内容 | 结论 / 教训 / 问题 | 数据 / 规则 / 轮次产出 |
| 稳定性 | 稳定，长期累积 | 随轮次增长，数据随开奖更新 |

**例外**：`FACTS.jsonl` 的每条都有 `game` 字段。彩种专属结论也进总台账，
但用 `game` 字段区分（跨彩种通用结论填 `global`）。
这样做的理由：**结论的可检索性比物理隔离更重要** —— 一个 AI 不应该为了
查"某条结论是否已有"而遍历所有彩种目录。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把待办写进 `FACTS.jsonl` | 台账污染，无法机器解析 | 待办进 `workbench/TODO.md` |
| 把假设当结论写进台账 | 下游引用未验证的东西 | 假设先放 `HYPOTHESES.md` |
| 删除被推翻的结论 | 下一轮重走弯路 | 标 `refuted` 保留 |
| 只写真结论不写 caveats | 下游误用，无失效边界 | caveats 必填 |
| 把教训写在 journal 里 | 没人会去重读日志，于是重犯 | 教训进 `lessons/LESSONS.md` |
| 只写日志不更新工作记忆 | 下一轮不知道该从哪继续 | 每轮必须清算 workbench |
