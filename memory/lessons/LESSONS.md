## L1 — 对过度离散计数数据用 Poisson 回归

| 项 | 内容 |
|---|---|
| **症状** | 计数因变量的 `var/mean` 远大于 1，模型却假设二者相等 |
| **后果** | 标准误严重低估 → t 值虚高 → 伪显著 |
| **实证** | 一等奖注数 `var/mean = 8.46`（Poisson 要求 = 1），GLM 报 heat IRR=1.025、p<0.001 |
| **正确做法** | 先算 `var/mean`；>1.5 则禁用 Poisson，改 QuasiPoisson / NegBin2，并配 HAC 稳健标准误 |
| **检测** | 建模前固定执行：`print(df[y].var()/df[y].mean())` |
| **相关结论** | F-0009 |
| **脚本** | `games/dlt/data/tools/overdispersion_and_hac.py` |

> ⚠️ **反面陷阱**：改用 NegBin 后 heat 又"显著"了（p=2.6e-11）。
> **换模型让结论变显著，不等于结论正确** —— 还要查共线、查口径、查分期。
> 决定性判据是 HAC + 分期稳定性，不是模型族选择的自由度。

## L2 — 对小期望频数格用渐近卡方检验

| 项 | 内容 |
|---|---|
| **症状** | 列联表中有期望频数 < 5（或贡献占比异常）的格 |
| **后果** | 卡方统计量被少数小格主导 → 伪显著 |
| **实证** | 奇偶分布渐近卡方 χ²=44.49 → p<1e-6；蒙特卡洛精确检验 χ²=8.85 → p=0.126（**不显著**） |
| **正确做法** | 期望频数 < 5 的格一律用蒙特卡洛精确检验（B=10000+） |
| **检测** | 检验前打印 `(observed/expected).min()`，关注最小期望频数 |
| **相关结论** | F-0010 |
| **脚本** | `games/dlt/data/tools/exact_tests.py` |

## L3 — 变点检测用"自然年硬切"

| 项 | 内容 |
|---|---|
| **症状** | 按 `year` 分组做前后对比，然后宣称"某年发生了断点" |
| **后果** | 断点定位错误（历史上偏了近 2 年），且掩盖了"渐变 vs 突变"的区别 |
| **实证** | 硬切得 2015 年；全候选切点扫描得 2013-08-28（χ²=185.0，排名 1/234） |
| **正确做法** | ① 全候选切点扫描（`t` 从 300 到 `n-300`，步长 ≤10）；② `ruptures` 多模型（Pelt/Binseg × l2/rbf）交叉验证；③ 画"切点-统计量"曲线判断峰形；④ 用宽峰判断渐变 |
| **检测** | 报告中若出现"2015 年之前/之后"这类按年表述，立即质疑 |
| **相关结论** | F-0006 · F-0007 |
| **脚本** | `games/dlt/data/tools/changepoint_scan.py`、`changepoint_refine.py` |

> **扩展教训**：变点分析还应检查**混杂物是否同位置**。
> 2013-08 前后无规则变更 → 可排除"规则导致号码突变"。
> 归因时"能排除什么"往往比"能证明什么"更有价值。

## L4 — 用 FDR 校正替代置换检验

| 项 | 内容 |
|---|---|
| **症状** | 多重比较只用 BH-FDR，未构造经验零分布 |
| **后果** | 无法判定"存活项"是真信号还是多重比较产物；也无法测其预测价值 |
| **实证** | ACF lag 6/10/18/23 在 FDR 后存活，报告自身承认"矛盾点未彻底查清" |
| **正确做法** | ① 置换检验（打乱 ≥10000 次）得每个 lag 的经验零分布；② 家族错误率校正（max\|r\| 联合检验）；③ **必须做样本外时间序列外推**并报告 R² |
| **检测** | 任何"显著"结论缺样本外验证，一律标 `tentative` 而非 `established` |
| **相关结论** | F-0008 |
| **脚本** | `games/dlt/data/tools/acf_permutation_test.py` |

> **关键区分**：置换 p=0.0004 说明"信号是真的"，样本外 R²=−0.083 说明"信号没用"。
> **这两件事不矛盾。** 把"统计显著"读成"可用"是最常见的越界。

## L5 — 对重尾变量比较均值

| 项 | 内容 |
|---|---|
| **症状** | 用 `mean` 比较两组重尾分布（如中奖注数） |
| **后果** | 均值被极端值主导 → 结论可能完全反转 |
| **实证** | 一等奖注数：均值 3.86 / 中位 2 / 最大 106 / var/mean=8.46 |
| **正确做法** | 用中位数/分位数描述；非参检验（Mann-Whitney U）或 GLM（含过度离散校正）；效应量报 IRR 而非均值差 |
| **检测** | 报告里出现"平均中奖注数"这类词，先查分布斜度 |
| **相关结论** | F-0003 · **F-0018（r03 已清偿，见下）** |

> **✅ r03 技术债清偿**：`round03/T-002` 已补做**中位数比**对照 —— 一等奖注数中位数比 **1.5**（Bootstrap CI [1.5, 2.0]），
> 与均值比 1.3603 **同向**；P99 截尾敏感性检验仅使估计变化 **1.72%**。
> 均值比与中位数比口径一致 → 本教训的历史欠账已注销。详见 F-0018 与 `round03/scripts/b2_robust_estimators.py`。

> **自我审视（已结案）**：`F-0003` 的 1.3603 是**均值比**，曾触及本教训。
> 缓解措施是二等奖（样本量约 80 倍）独立同向确认 + Bootstrap CI，但**未做中位数比对照**。
> **r03 T-002 已补齐**：中位数比 1.5 [1.5, 2.0] 同向，截尾敏感性 1.72% → 欠账注销（F-0018）。

## L6 — 用全样本统计量做"预测"（前视偏差）

| 项 | 内容 |
|---|---|
| **症状** | 第 `t` 期的特征用到了 `t` 期之后的数据 |
| **后果** | 特征泄露 → 伪显著、伪可预测 |
| **实证** | `heat` 用全样本频率定义，本质是"该组合在未来是否高频出现"的代理，与销量强混杂 |
| **正确做法** | 逐期滚动：`cum` 只累加到 `t-1`。见 known_errors 的 `heat_past` 示例代码 |
| **检测** | 任何"预测"类分析，先问："这个特征在第 t 期是怎么算出来的？" |
| **相关结论** | F-0009 |
| **脚本** | `games/dlt/data/tools/_load.py` 的 `heat` 是**全样本口径**，仅供复现历史讨论 |

## L7 — 混淆"开出率"与"被选中率"

| 项 | 内容 |
|---|---|
| **症状** | 把"某形态被摇出的频率"与"某形态被彩民购买的密度"当成同一个量 |
| **后果** | 因果解释错误 —— 策略价值来自后者，却用前者的证据去支撑 |
| **实证** | 开出率：连号比值 1.120（仅早期，不可用）；被选中率：一等奖注数比 1.360（强，可用） |
| **正确做法** | 两个概念在报告中**必须用不同小节、不同措辞**；理论开出分布用精确枚举（枚举全部 324632 组合）而非近似 |
| **检测** | 若某段同时出现"更易开出"和"更多人中"，立即要求拆分 |
| **相关结论** | F-0003 · F-0005 · **F-0011 → F-0025（r04 第二实例）** |
| **脚本** | `games/dlt/data/tools/consecutive_exact_check.py` |

> **r04 第二实例（同一教训的另一种形态）**：`F-0011` 里写过「后区号码不存在可利用的偏好结构」，
> 但它的证据全是**开出率**（66 组合频次 vs 均匀期望，χ²=64.09，MC p=0.51）。
> r04 用注数反推**被选中率**后发现：后区人群密度**强烈非均匀**（过散布 8.72×，最热/最冷对密度比 2.25×）—— F-0025。
> 该结论已被修正（F-0011 的 caveats + claim 措辞）。
> 与 L7 的第一实例（连号）不同：第一实例是**把两个量当成同一个**；第二实例是**用一个量的证据支撑另一个量的结论**。
> 两者都归本教训，检测方法相同：同一段里若「频率」与「密度」指向同一对象，立即要求拆成两节。

## L8 — 用模拟去"验证"本可解析证明的事实

| 项 | 内容 |
|---|---|
| **症状** | 写大循环模拟"技巧 vs 随机"的一等奖命中，试图"证明"技巧无效/有效 |
| **后果** | 一等奖概率 4.667e-08 → 有限算力下命中数几乎恒为 0，结论**完全由采样噪声主导**，既证不了也驳不了 |
| **实证** | 200,000 次试验中技巧 4 次、随机 1 次，理论期望各 0.9335 —— 纯粹是噪声 |
| **正确做法** | 按主张类型选方法：<br>· 概率不变性 → **解析给出**<br>· 形态被摇出频率 → **精确枚举**<br>· 形态人群密度 → **观测量 + Bootstrap CI**<br>· 中奖时奖金 → **条件份额模拟**（唯一必须模拟的量）<br>· "能否统计检验" → **功效分析** |
| **检测** | 任何 `for` 循环里出现"是否中一等奖"的判断，立即质疑设计 |
| **相关结论** | F-0001 · F-0004 |
| **脚本** | `games/dlt/strategy/strategy_simulation.py` |

> **本教训的核心是"边界意识"**：模拟不是万能的，它有明确的能力边界。
> 越过边界使用它，得到的数字看起来精确，实际毫无信息。

## L10 — 把"规则文本里写了"当成"现实中发生过"

| 项 | 内容 |
|---|---|
| **症状** | 读到规则条款（如"单期一等奖总额封顶 1 亿元"）后，直接假定它在数据里被触发过，并据此计算"封顶后的影响" |
| **后果** | 归因错误 —— 为一个**从未发生**的事件构造了"影响修正"，掩盖了真实的调参问题；且该错误会以"已实测"的措辞写进结论库，污染后续所有引用 |
| **实证** | `F-0015` 曾断言"封顶已在 26113 期实测触发"。实盘复核：E6（≥26014）全部 **102 期**一等奖总额最大值仅 **0.9788 亿元**（26060 期），封顶**一次都没触发** → `F-0015` 被 `F-0016` 取代 |
| **正确做法** | 任何"某规则已生效/已触发"的断言，**必须先做事件计数**（`trigger_count = (x >= threshold).sum()`），再谈影响；`trigger_count == 0` 时结论只能是"该条款在当前样本下未触发"，不能是"影响为 X%" |
| **检测** | 结论中出现"已触发/已生效/实测达到"等措辞时，立即追问：**触发次数是多少？写在哪一行日志/数据上？** 拿不出计数的，一律降为 `proposed` 或删除 |
| **相关结论** | F-0015（superseded）→ F-0016 · F-0017 |
| **脚本** | `games/dlt/iterations/round03/scripts/cap_adjusted_uplift.py`（S1 解析层：封顶触发统计 0/102） |

> **本条与 L8 的分工**：L8 说"别用模拟验证解析事实"；L10 说"别把条款文本当发生事实"。
> 前者关于**方法越界**，后者关于**证据层级**（规则文本 ≠ 观测事件）。
> 一个归因错误的完整伪装路径是：*条款存在* → *假定触发* → *模拟出影响* → *写进结论库*。
> 三层防护分别在：L10（先计数）、L8（先解析）、以及 `evidence.effect` 的字段设计（框架建议 R-6）。

## L11 — 用错误口径的锚点做外推

| 项 | 内容 |
|---|---|
| **症状** | 模拟/外推需要一个现实基准量，于是随手从一个"名字差不多"的字段里取，未核对该字段的真实语义 |
| **后果** | 锚点偏离真实值一两个数量级，整个模拟输出荒谬却不报错（数字看起来"很精确"） |
| **实证** | 首版用 `n0 = pool_yuan / amt_med` 估计"每期一等奖注数"，得 **1.7 注**；实际 `pool_yuan` 是**奖池余额**（约 7.9 亿，跨期滚存），不是当期一等奖可分配额。实测 `w1` 中位数是 **6 注** → 锚点错了约 3.5 倍 |
| **正确做法** | ① 锚点优先取**已经在数据里观测到的统计量**（`median(w1)`），而不是从别的量**反推**；② 若必须反推，先写出量纲/口径等式并逐项核对；③ 对锚点做**合理性区间检查**（如"每期一等奖注数应在 1~50 之间"），超出则中止 |
| **检测** | 任何"由 A 除以 B 得到基准量"的写法，先问：**A 和 B 是同一口径的吗？** 再看产出值是否落在常识区间内 |
| **相关结论** | F-0017（锚点已修正为实测口径） |
| **脚本** | `games/dlt/iterations/round03/scripts/cap_adjusted_uplift.py`（S2 实测锚点层，含 `why_fixed` 注释） |

> **口语版**：**名字像 ≠ 口径对**。奖池余额、当期可分配额、单注理论奖金是三个不同的量。
> 反推得到的锚点，其误差会被模拟层放大，且不会触发任何异常 —— 只会输出一个错的百分比。

## L12 — 未检查"新估计量"是否只是旧估计量的换皮

| 项 | 内容 |
|---|---|
| **症状** | 为求稳健，引入一个"不同的"估计量（如 GLM 的 IRR）来交叉验证已有结论，但未验证二者在数学上是否等价 |
| **后果** | 把**数值等价的两个量**当成"两条独立证据"，虚增了结论的置信度；实际上只有一条证据，另一条是它的重新表达 |
| **实证** | 对 `log` 链接的 NB2 模型，IRR = `exp(β1)`，而均值比也等于 `exp(β1)`（因为 `E[Y|X]=exp(β0+β1·x)`，组的 IRR 之比恰为 `x` 每增 1 单位的 `exp(β1)`）。实测：NB2 IRR = **1.3603**，均值比 = **1.3603**，**完全相等** → 相关系数为 1，不构成独立证据 |
| **正确做法** | ① 引入新估计量时，**先问它和旧的有什么函数关系**；② 要求新估计量在**变换不变性**上与原估计量不同（如中位数比 vs 均值比，前者对重尾/极端值稳健，后者不稳健 —— 这才是真正的独立口径）；③ 结论中显式声明"哪些是独立证据，哪些是同一证据的换皮" |
| **检测** | 结论中出现"两套方法互相印证"时，立即核对：**两套方法的点估计是否数值相同或成固定比例？** 相同则不构成交叉验证 |
| **相关结论** | F-0018（独立口径 = 中位数比，非 NB2 IRR） |
| **脚本** | `games/dlt/iterations/round03/scripts/b2_robust_estimators.py`（含 `★_caveat_on_independence` 标注） |

> **口语版**：**换个名字不算换个人证**。
> 真正的交叉验证要求两条证据在**失效模式**上不同 ——
> 均值比怕极端值、中位数比不怕；如果新估计量同样怕，那它只是同一把尺子量了两遍。

## L13 — 把「同一个数字」当成「同一个结论」，忽略口径自由度

| 项 | 内容 |
|---|---|
| **症状** | 报告一个相对幅度（如「下降了一半」「提升 121%」），但没写用的是哪个估计量（均值 / 中位数 / 截尾 / 剔极端期） |
| **后果** | 同一份数据、同一个效应，换个估计量就换一个故事；而两个数都「算对了」。读者会按最耸动的那个记 |
| **实证** | `F-0003` 的分期衰减：**均值比口径** post/pre = 0.592（w1）/ 0.498（w2）→「衰减过半」；
| | **稳健口径**（中位数比 / 10% 截尾 / 剔除 top3）只有 0.721 ~ 0.834 →「温和弱化」。
| | 前段 w1 的均值比 2.107，剔掉**最大 1 期**后就变成 1.719、剔 3 期变 1.466；前段中位数比是 1.000。
| **正确做法** | ① 任何相对幅度必须**同时给出估计量口径**；② 重尾 / 稀疏计数场景**默认用稳健口径**（中位数 / 截尾），均值比只作对照；③ 至少给出一种「剔除极端值后是否仍成立」的检验；④ 两个口径都报时，明确哪个用于对外 |
| **检测** | 报告里出现「减半 / 翻倍 / 提升 N%」时，追问：**换成中位数比或截尾比，还是这个数吗？剔掉最大 3 期呢？** 变化超过 20% 就必须并列报告 |
| **相关结论** | F-0020（本条的直接来源）· F-0003 · F-0018 |
| **脚本** | `games/dlt/iterations/round04/scripts/decay_cause.py`（S2 多估计量对照） |

> **口语版**：**数字没有错，尺子有两把。** 报告不写尺子，等于让读者自己挑一把 — 而读者总会挑最响的那把。
> 与 L5（重尾禁止比均值）的分工：L5 说「这类数据别用均值」；L13 说「**任何时候都要报出你用的是哪把尺子，并做稳健对照**」。

## L14 — 跨段比较之前，没先验证各段自身是否自洽

| 项 | 内容 |
|---|---|
| **症状** | 把数据切成前/后段比较某个量（比值、均值、效应量），但**没有先检查各段内部是否自洽** |
| **后果** | 若某段的数据在几个可核对的量之间互相矛盾，那段的「水平」就不是真实水平。此时任何跨段差异都可能只是**数据差异**，却被读成**行为差异** |
| **实证** | `F-0019`：2013-08 之前那段数据里 —— ① 前区号码分布 χ²=251.5（P(全部<=31)=0.395 vs 理论 0.5234，z=−7.98）；② 由中出注数反推的投注量**超出售额允许上限**（均价 1.75~1.87 元/注 < 最低票价 2 元）；③ 且两项异常**方向相反**（高端号超发本应让中出注数偏低）。后段两项都自洽（χ²=32.1、均价 2.33~2.42）。于是 r03 的「前段 2.11 → 后段 1.25」里，前段的 2.11 **不能**当作纯人群行为基线 |
| **正确做法** | ① 切段之后、比较之前，先做**可行性核算**：反推出来的量是否落在物理/规则允许的区间（票价 ≥2 元、注数 ≤ 销售额/最低票价）；② 做**分布检验**（号码分布 vs 精确均匀）；③ 检查该段的记录方式字段（是否有校验标志、覆盖率为 0）；④ 不自洽的段只能用于**描述**，不能用作**基线**；⑤ 处置写成「哪一侧错**未判定**」也是合格结论 |
| **检测** | 任何跨段比较的报告，先问三句：**这段的数据自己前后对得上吗？反推量落在允许区间吗？记录方式与另一段相同吗？** 三问没有答案，比较结论一律标 `tentative` |
| **相关结论** | F-0019 · F-0020 · F-0021 · F-0006 |
| **脚本** | `games/dlt/iterations/round04/scripts/decay_cause.py`（S1 数据口径层） |

> **口语版**：**先确认尺子本身没坏，再去量两段长短。**
> 与 L11（锚点口径不可反推）的分工：L11 管「某个基准量取得对不对」；L14 管「**整段数据能不能当基线**」。

## L15 — 研究脚本的命中清单必须全量核对；校验器检查范围禁止手写白名单

| 项 | 内容 |
|---|---|
| **症状** | ① 修复轮里，研究脚本产出了「命中清单」（如 t050 的 184 处），但修复时**只挑了部分文件改**，清单里剩下的没逐一分类核对；② 校验器（validate）用**手写文件白名单**，与全仓扫描不一致——白名单没列的文件，机械护栏永远看不见 |

| **实证** | r10 T-050：t050_calibration.py 全仓扫描命中 184 处（**含 STRATEGY_GUIDE.md**），修复计划只列 7 份文档；`_PROB_CALIBRATION_FILES` 手写 11 份不含 STRATEGY_GUIDE.md/api.py/MATH_BOUNDARY。r10.1 把检查范围改为**自动派生**（versions.json 受管表 + docs/ 全量），立即抓到全部漏网 |
| **正确做法** | ① 研究脚本的命中清单**必须逐条分类**（真数字错误 / 语义正确 / 规则引述），全部处理完才能收尾——「先看清单全貌，再动手改」；② 校验器检查范围**从登记表自动派生**（受管文件全集），删除手写白名单；③ 规则描述类文本（四件套/OQ 验收判据）用「名词引用豁免」（『中奖概率』带闭合引号 → 跳过），而不是从扫描清单里剔除文件 |
| **检测** | ① 修复轮收尾前问：命中清单里的每一项，属于「改了 / 判为正确 / 豁免」哪一类？有未分类的项 = 未完成；② validate 源码里 grep 手写文件清单常量 → 应不存在，检查范围应来自 versions.json 派生 |

## 新增教训的操作步骤

1. **先判断是不是教训**：它能否阻止下一轮犯同样的错？不能则并入 `FACTS.jsonl` 的 `caveats`
2. 追加到本文件末尾，编号 `L<n>` 递增（**永不复用**）
3. 必含四段：**症状 / 后果 / 正确做法 / 检测方法**
4. 关联到具体 `F-xxxx` 与复现脚本路径 —— 教训不能是孤立的感慨
5. 若某条教训暴露了**已有结论的未偿技术债**，必须写进下一轮 `TASK_BRIEF.md`

> 注意：教训库**只增不删**。即使某条教训后来被证明不适用，
> 也应新增一条说明，而不是删掉原来的（保留"我们曾经这么想"的记录）。
