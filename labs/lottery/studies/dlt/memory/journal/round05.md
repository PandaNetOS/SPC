## 2. T-205：投注方式 —— R-002 的账，终于算清了

**S1 等价性（F-0026）**：单注/复式/胆拖/倍投/追加的「每元期望回报率」数学等价。
这个结论 STRATEGY_GUIDE §6 早就用直觉写过（"拆成单注买还是合成多注买，期望完全一样"），
本轮把它从直觉升级为解析结论 —— 复式 = C(m,5) 注单式、胆拖 = C(q,5−p) 注展开、倍投 = 线性放大，
全部落在 51% 返奖率内。**投注方式不改变期望，只改变两件事：撞号水平和组内重复。**

**S2 自我摊薄（F-0027）**：买 K 注**完全相同**的号码，中奖时 K 注同中一等奖、总奖金被 K 份瓜分。
公式 (1+m)/(K+m)：K=10、锚点 m=6 时，每元期望回报只剩 43.8%（损失 56%）。
这是「重复」真正有害的形式。

**S3 凯利**：返奖率 51% → 每注期望净收益 −0.98 元 → f* ≤ 0。数学上的最优投注金额是 0。
（并入 F-0026，不单列 —— 与 F-0002 同一立场。）

**S4 R-002 量化（Q-012，F-0028）** —— 本轮最重的一击：

| 指标 | spread（分散） | cluster（同构） | 差异（CI） |
|---|---|---|---|
| 期望撞号系数 | 0.4760 | 0.5003 | +0.024 [−0.011, 0.064] 含 0 |
| 未计封顶每注奖金 | 1490.6 万 | 1417.0 万 | +5.24% [−2.13, 14.29] 含 0 |
| 撞号系数标准差 | 0.0172 | 0.0105 | **同构组反而更低** |

R-002 判定的「结构同构」（gap 向量相同、号码不同）**既不提高期望奖金，也不增加方差**。
按 Q-012 验收判据：CI 含 0 → `not_established`，权重 0.5 应改 1.0。
**而真正有害的「重复」—— 完全相同号码 —— R-002 的 predicate 根本抓不到。**

> 这轮最重要的策略教训：**R-002 的 0.5 是拍的，量化后不成立；它抓错了对象。**

**S5 R-003 候选（F-0029）**：在避开连号（R-001）之上，再避开生日号区（max≤31），
覆盖集合的人群权重恒为 1.0 → 撞号系数 0.476 → **0.425**，未计封顶 +111% → **+136%（增量 +25pp）**。
含封顶在锚点 n0=6 处被单注上限抹平（两者同为 +41.8%），在注数多（n0=9）时显现（+112% vs +111%）。
若用户批准，这是第一条对 F-0004 模型增益的候选规则。

## 3. T-206：时间因素 —— 又一个负结论，但方向出乎意料

**S1 星期×撞号（H-005，F-0030）**：H-005 假设「周六销量最高 → 撞号更强」。
数据给出**相反方向**：后段 NB2（控制销量）的 run×周六 交互显著为负 ——
w1 −0.268（p=0.039）、**w2 −0.607（p<0.0001）**，即**周六的连号撞号效应更弱**（尤其二等奖口径）。
Bootstrap 两两差 CI 全含 0（噪声大），Holm 校正后仅 w2 保留。

解释方向：高销量期有更多随机/非偏好型买家，稀释了连号密度 —— 与「休闲型购彩者」的假设直觉相反。
但幅度不足以择时 → **H-005 标 refuted，维持 F-0023/A-009**。

**S2 奖池时序（F-0031）**：AR(1) 斜率 0.9994、ACF≈1.0 —— 奖池几乎完全由上期滚存决定。
「可预测 ≠ 可利用」：F-0023 已证奖池分位对期望派发无稳健差异。这条把 F-0023 的机制补全了。

**S3 节假日窗口（F-0032 → H-006）**：国庆/元旦窗口的一等奖连号比低于基线
（0.72/0.73 vs 1.28/1.27），销量略低（休市）。样本小（n=82/67）、CI 宽 → **tentative**。
方向与 F-0030 的「人群构成稀释」解释同源 —— 开 H-006 待下轮用农历精确映射验证。

## 4. 这轮踩的坑

| 坑 | 后果 | 教训 |
|---|---|---|
| 首次跑 bet_structure 时 cluster 模拟用重复号码补足同构组 | 52.9% 的模拟混入「自我摊薄」，污染结构同构的测量 | 设计模拟前先检查「同构组大小分布」（中位数只有 6）—— 补足策略会改变被测量对象 |
| S4 奖金全部饱和在 1000 万单注上限 | spread/cluster 差异显示为 0%，差点误判「无差异」 | 必须先分 nocap / with_cap 双口径，再下结论（F-0017 的教训重现） |
| weekday 列是单字（一/三/六）不是「周一」 | 分组全空 → 脚本崩 | 数据字段先探查再写匹配逻辑 |
