### 2.2 T-003 第 1 步：解析层分析 → 发现 F-0015 错了

**这是本轮最重要的时刻。**

原计划是"把封顶加进模拟"。但按 **L8（不得用模拟验证解析事实）**，
第一步应该先做**解析层**：封顶到底触发过没有？

结果：

| 项 | 实测 |
|---|---|
| E6（>=26014）期数 | 102 |
| 一等奖总额最大值 | **0.9788 亿**（26060 期） |
| 达到 1 亿封顶的期数 | **0 / 102** |
| 26113 期总额 | **0.8852 亿** < 1 亿 → **未触发** |

→ **一个整数期都没有触发过封顶。**

而 `F-0015` 的 claim 是"26113 期触发了 1 亿封顶"，`confidence: 5`。

**根因**：`F-0015` 把"37 注导致单注 239 万"这个**自然摊薄**现象，
误读为"封顶触发"。239 万这个**数字是对的**，但**归因错了**。

### 2.3 自我更正：`rules_history.md` 也曾被我误判

过程中我一度认为 `rules_history.md` §3.3（"单注最高 500 万"）与实测
（最大 1000 万）矛盾，准备改文档。**联网核实官方规则后更正**：

> 500 万是「**每部分**」上限；奖池 ≥1 亿时一等奖分两部分（58%+20% / 20%+40%）
> → **合计上限 1000 万**。实测 1000.0 万完全吻合。

**结论**：文档措辞不精确但**不算错**。用户确认：标记存疑，本轮**不改该文档**。

### 2.4 T-003 第 2 步：写模拟脚本，第一次跑出荒谬锚点

写完 `cap_adjusted_uplift.py` 首次运行，S2/S3 输出：

```
[锚点] 反推基准当期总注数 n0 = Pool/amt_med = 1.7 注
```

**1.7 注** 显然荒谬 —— 实测 `w1` 中位数是 **6 注**。

**根因**：`pool_yuan` 是**奖池余额**（约 7.9 亿），不是"当期一等奖可分配额"。
拿它除以单注金额，没有任何物理意义。

**修正**：锚点直接取**实测可观测统计量**：
- `n0` = 中出注数 `w1` 的中位数 = **6 注**
- `Pool` = 总派发额 `w1×amt1` 的中位数 = **0.4252 亿**

→ 这成为**L11（锚点口径不可反推）**的由来。

### 2.5 T-003 第 3 步：三档情形

| 情形 | n0 | uplift（含封顶） | 说明 |
|---|---|---|---|
| anchor | 6 注 | **41.42%** | 实测锚点 |
| anchor_lo | 3 注 | **0.00%** | 两侧未封顶单注（1414万/3130万）均超 1000 万上限 → **被抹平** |
| anchor_hi | 9 注 | **112.12%** | |

`anchor_lo` 的 0% 一开始像 bug，实际是**封顶的真实作用**：
当两家未封顶单注都超过单注上限时，被同一上限压平，收益差消失。
我在脚本里加了显式机制标注。

### 2.6 T-001：分期稳健性 → 又一个意外

切点用 F-0006 的 **2013-08-28**（不用自然年 —— L3）：

| 段 | 一等奖比 | 二等奖比 |
|---|---|---|
| 前段 960 期 | **2.1072** [1.3213, 3.2616] | **2.4250** [1.5817, 3.5869] |
| 后段 1973 期 | **1.2472** [1.0315, 1.4907] | **1.2075** [1.0475, 1.4093] |

我的**第一版自动判据**只检查"符号一致 + CI 下界 >1"，得出"效应稳定、无需限定时段"。

**这个结论是误导性的。** 因为：
- 幅度**衰减过半**（后/前 = 0.592 / 0.498）
- 二等奖两段 **CI 不重叠** → 衰减**统计显著**
- 后段 CI 下界仅 1.03 / 1.05，**逼近零效应边界**

这正是 round02 预警的模式（"其它结论都在分期后发现仅早期显著"），
只是**性质不同**：不是"仅早期显著"，而是"稳定但衰减"。

**修正**：判据扩展两个维度——判据4（幅度衰减比 <0.70）、判据5（后段 CI 下界 <1.10）。

### 2.7 T-002：稳健估计量 → 第三次技术修正

第一版用 `sm.GLM(NegativeBinomial(alpha=None))` → alpha 被固定为默认 1.0，
且 `get_robustcov_results(cov_type="HAC")` 对 GLM **静默失败**（返回 None）。

**修正**：改用 `sm.NegativeBinomial`（MLE 同时估 α 与 β）+ `cov_kwds` 指定 HAC。

结果：alpha_MLE = 1.0034、IRR = 1.3603、HAC CI [1.1352, 1.6301]。

**又发现一个问题**：NB2 log 链接下 `IRR ≡ 均值比`（数值上完全相等）。
所以 **IRR 不是独立证据**。真正独立的是**中位数比 1.5**。
我在脚本与文档里都显式标注了这一点 → **L12（估计量独立性检查）**。
