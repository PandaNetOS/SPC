## 2. T-101：一次"元复核"

r03 已经做过分期（`b2_split_stability.py`），结论是"幅度衰减过半（0.592 / 0.498）"。
本轮的第一件事就是**先把 r03 的数字复现出来**（S0），确认可比，然后分四层拆：

1. **数据口径层（S1）**：这一层本来只是"排除项"，结果成了本轮最大的发现。
   前段的前区号码分布 χ²=251.5（P(全部<=31)=0.395 vs 理论 0.5234，z=−7.98），
   而且**由中出注数反推的投注量超出售额允许上限**（均价 1.75~1.87 元/注，低于最低票价 2 元）。
   两项异常还**方向相反**：前段"高端号超发"本应让 w1 偏低，实测却偏高。
   后段两项都自洽（χ²=32.1 与 F-0006 记录一字不差；均价 2.33~2.42 元/注）。
   → 这不是"早期效应更强"，而是"**早期那段数据不能当基线**"。

2. **估计量稳健性层（S2）**：把 r03 用的均值比与中位数/截尾/Jackknife 并列。
   前段 w1 的均值比 2.107 在剔掉最大的 1 期后变成 1.719，剔 3 期变 1.466；
   前段中位数比是 1.000（两组中位数都是 1）。
   用样本量约 80 倍的二等奖（w2）做稳健口径：衰减比 0.721（截尾）/ 0.834（中位数）。
   → **同样的数据，"减半"变成"减三成"**。这是本轮的第二大发现。

3. **规模与成分控制层（S3）**：用 `log(销量/2)` 作 offset 的 NB2，交互 IRR=0.596（p=7e-5）→
   **销量稀释不是主因**；分层标准化（MH）后衰减比 0.627；滚动窗口数据驱动最优切点 2013-04，
   四种窗口设定都落在 2013~2014 初，与 F-0006 的号码结构变点（2013-08）**同期**。

4. **口径重算（S4）**：把 α 从全样本 13.9405 换成后段 12.7815，重算条件份额与封顶后处理。
   意外发现：**含封顶净值几乎不动**（41.0% → 40.6%），因为锚点处单注已被 1000 万上限饱和；
   动的是**未计封顶的上界**（121% → 109%）。

## 3. T-102 / T-103：分权与复核

两条任务线相对独立（择时 / 后区），我把它们下发给了两个隔离子代理，并给了明确的设计边界与纪律清单
（L1–L12 逐条点名、必须写 JSON、不得改仓库其它文件）。两个子代理都做了很扎实的工作，但也都没有可用 shell ——
于是它们**在会话内用 Node 等价复刻了算法**并写出 JSON，同时把 Python 脚本留了下来。

我的处置是：
1. 用本机可用的 3.13 解释器（配 `detached:true` + 文件重定向）**实跑两份 Python 脚本**，覆盖 JSON；
2. 对比 Node 版与 Python 版的关键数字（Tobit 系数、bootstrap p 值、uplift）→ 基本一致，
   等于**两种独立实现互相验证**；
3. 逐条检查识别假设与 caveats，确认没有越界表述（红线：不声称改变中奖概率）。

**两条线的产出都是负结论，而且都很有用**：
- T-102：**不存在稳健的"奖池累积期 → 高期望"择时机会**。全局看似 +0.090 的正差，
  在 E4 剔除 2019（奖池 73 亿→8 亿的一次性排空）后归零；现行 E6 不显著。
  顺带发现一个**口径陷阱**：用"派发额/销售额"衡量择时会被"每注均价"的组成效应骗过（L12 的新实例）。
- T-103：后区**开出率均匀**（MC p=0.51）但**被选中率强烈非均匀**（过散布 8.72×，最热/最冷对 2.25×）。
  结构是真的，但**不可靠利用**：前/后段交叉验证的避让收益 K=5/10 只有 1.1%/3.0%，95%CI 含 0。
  同时它**修正了 F-0011**：那条结论拿"开出频率均匀"支撑了"人群偏好均匀"，是 L7 的另一个实例。

## 4. 这轮踩的坑

| 坑 | 后果 | 教训 |
|---|---|---|
| 把"均值比"当成"效应量" | 结论从"减半"变成"减三成"，且前段数字由个别期主导 | **L13 口径自由度** |
| 拿一段不自洽的数据当基线 | 会把数据差异读成行为差异 | **L14 分段自洽性前置检查** |
| 用开出频率支撑人群偏好 | 结论方向对、量词错 | L7 追加实例（F-0011 → F-0025） |

另外还有一次**工程性踩坑**：本机沙箱会阻断普通子进程（`pwsh` 与 venv 的 `python.exe` 都以
`0xC0000142` DLL init failed 退出），必须用 `detached:true` + 文件重定向才能执行；
子代理会话里连这条路都不通，只能先在会话内用 Node 复刻、再由我把 Python 脚本实跑复核。
这件事本身值得写进 HANDOFF 的环境注意事项（已写）。
