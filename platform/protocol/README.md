# platform/protocol/ — 协议层

> **版本**：`1.0` ｜ 轮次 `r02` ｜ 更新 2026-10-11 ｜ 权威源 `VERSION_INDEX.md`
> 版本规则见 `docs/VERSIONING_DOCS.md`

> 本目录定义**"在这个仓库里怎么做研究"**。它是彩种无关的 —— 换任何彩种都适用。

## 文件

| 文件 | 定义什么 | 谁必须读 |
|---|---|---|
| `ITERATION_PROTOCOL.md` | 一轮研究的完整生命周期（四件套、开轮/收轮流程、禁止事项） | **每个执行者** |
| `MEMORY_PROTOCOL.md` | 记忆层的读写规则（四类记忆、状态机、演化链、置信度标准） | **每个执行者** |
| `templates/` | 三个交接模板 | 开轮/收轮时 |

## 三分钟上手

```
开轮：复制 templates/TASK_BRIEF.template.md → 填目标与验收判据
做分析：按 FINDINGS.template.md 记录，每个数字配一个脚本
收轮：写 HANDOFF.md → 生成下轮 TASK_BRIEF.md → 更新 memory/
```

## 两条不能省的

1. **结论的 `caveats` 非空** → 每条 caveat 转化为一个 `OPEN_QUESTION`
   （这是自我迭代的动力源，省掉它系统就退化成"一份文档"）
2. **收轮必须生成下一轮 `TASK_BRIEF.md`**
   （省掉它迭代链断裂，下轮从零开始问"该做什么"）

## 为什么协议要写成文件

因为这些规则**看起来都是常识，但每一条都是历史上踩坑后才总结出来的**：

| 协议条款 | 对应的坑 |
|---|---|
| 结论的 `caveats` 必须非空 | 减损项写完就丢，下轮重犯（v4 的 `04_priority_tasks.md` 里写着"未做分期稳健性"，但没有机制保证它进下轮任务） |
| 被推翻的结论不删除 | 删掉后重走弯路（L3 的"自然年硬切"被走过两次） |
| `supersedes` 双向一致 | 单向填写导致演化链断裂 |
| 区分「解析/枚举/观测/模拟」 | L8：用模拟验证解析事实 |
| 必须声明 `rules_epoch` | L9：跨规则断点比奖金 |
| 反锚定：任务书不给期望结论 | 原 v4 任务书设计，防止执行者朝期望方向找证据 |

> **协议不是形式主义** —— 它是把已付的学费固化成流程。
> 若发现某个条款没有历史依据，可以提 R 提案删掉它（见 HANDOFF 模板第 4 节）。
