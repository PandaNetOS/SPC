## 0. 什么时候需要因果推断

**不需要因果推断的场景**：
- 描述性统计（"形态 X 的出现频率是多少"）
- 预测（"根据历史数据，下期号码是什么"）—— 预测不需要因果
- 策略提取（"选什么号码能降低撞号"）—— 这是描述性，不是因果

**需要因果推断的场景**：
- "规则变更导致了奖金分布变化"
- "彩民行为变化导致了撞号率变化"
- "球组更换导致了号码频率变化"

---

## 1. DAG（有向无环图）

**核心思想**：先画清楚谁影响谁，再决定怎么估计因果效应。

```
示例：规则变更 → 奖金池 → 中奖注数 → 撞号率
      ↓
    销量 → 中奖注数
```

**DAG 工具**：
- 手画（简单场景）
- `networkx` 库（复杂场景）
- 检查后门路径：是否有混杂变量同时影响处理和结果

**判断标准**：
- 如果有后门路径 → 需要匹配 / 回归控制 / 工具变量
- 如果没有后门路径 → 直接回归即可

## 2. RDD（断点回归）

**适用场景**：处理变量在某个阈值处有跳跃（如规则变更日）。

**设计**：
```
处理组：规则变更后 t > t0
对照组：规则变更前 t < t0
在 t0 附近比较两组的结果差异
```

**操作步骤**：
1. 找到断点 t0（如规则变更日）
2. 在 t0 两侧选带宽（如 ±30 天）
3. 比较断点两侧的结果均值差
4. 检验：这个差异是不是"跳跃"（连续 vs 不连续）

**代码模板**：
```python
import numpy as np
from scipy import stats

def rdd_estimate(data, breakpoint, bandwidth):
    """断点回归估计。"""
    treated = data[(data.time >= breakpoint) & (data.time < breakpoint + bandwidth)]
    control = data[(data.time < breakpoint) & (data.time >= breakpoint - bandwidth)]
    effect = treated.outcome.mean() - control.outcome.mean()
    se = np.sqrt(treated.outcome.var()/len(treated) + control.outcome.var()/len(control))
    return effect, se
```

## 3. DID（双重差分）

**适用场景**：有处理组和对照组，处理组在某个时间点接受了处理。

**设计**：
```
处理组前后变化 - 对照组前后变化 = 净效应
```

**操作步骤**：
1. 选处理组（受规则变更影响的彩民）
2. 选对照组（不受影响的彩民）
3. 计算处理组前后差
4. 计算对照组前后差
5. DID = 处理组前后差 - 对照组前后差

**平行趋势假设**（必须检验）：
- 处理前，两组的变化趋势应该平行
- 如果不平行 → DID 不可信

## 4. IV（工具变量）

**适用场景**：有混杂变量无法观测，需要找一个"只影响处理、不影响结果"的工具变量。

**好的工具变量三条件**：
1. **相关性**：工具变量与处理变量相关
2. **外生性**：工具变量与结果变量不直接相关（只通过处理影响）
3. **排他性**：工具变量不通过其他路径影响结果

**示例**：
- 工具变量：气温（影响销量，但不直接影响中奖注数）
- 处理：销量
- 结果：中奖注数
- 逻辑：气温 → 销量 → 中奖注数（没有其他路径）

## 5. 本项目的因果推断机会

| 问题 | 方法 | 数据可得性 |
|---|---|---|
| 规则变更对奖金分布的影响 | RDD | ✅ 有规则变更日期 |
| 销量对撞号率的影响 | IV（气温做工具） | ⚠️ 缺气温数据 |
| 彩民行为变化对撞号率的影响 | DID | ❌ 缺彩民分组数据 |

## 6. 归因边界声明

**本仓库能做的**：
- 观测相关（"A 和 B 同时变化"）
- RDD（规则变更日前后比较）

**本仓库不能做的**：
- 纯因果断言（无实验/准实验设计）
- 排除所有混杂变量
- 断言"设备/球组导致了号码变化"（无设备数据）

**写结论时必须声明**：
> "本结论为观测相关，不构成因果断言。需 RDD/DID/IV 等准实验设计才能下因果结论。"
